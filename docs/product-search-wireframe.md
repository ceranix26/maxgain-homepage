# Product Search 개편 — 1단계 화면 설계

작성일: 2026-11-19  
범위: 정보 구조와 표시 필드 확정. 이 문서는 구현 전 설계안이며 페이지 동작이나 데이터 파일은 변경하지 않는다.

> **설계 기록:** 현재 운영·후보 구분과 검증 경로는 [제품검색 백엔드 상태](PRODUCT-SEARCH-BACKEND.md)에서 확인한다. 이 와이어프레임의 버튼·필터 배치는 현재 배포 화면을 설명하지 않는다.

## 설계 원칙

- Part Number 검색을 첫 번째이자 가장 눈에 띄는 동작으로 둔다.
- 재고 검색 결과와 확인된 기술 정보를 한 화면에서 이어서 살펴볼 수 있게 한다.
- 제품/제조사/규격/문서는 데이터에 존재하고 출처가 확인된 경우에만 표시한다.
- 공개 재고는 상태 또는 승인된 구간으로 표시한다. 내부 수량과 ECOUNT 출처는 노출하지 않는다.
- 현재 정적 HTML/CSS/JavaScript 구조와 기존 데이터 파일을 유지한다.
- 한국어/영어와 키보드 접근성을 설계에 포함한다.

## 표시 필드와 데이터 근거

| 영역 | 필드 | 데이터 출처 | 표시 규칙 |
|---|---|---|---|
| 검색 | 검색어 | 사용자 입력 | Part Number exact/partial/alias 우선 + 제조사, 카테고리, 규격명/값, ECOUNT 품목그룹 코드 검색 |
| 검색 안내 | 검색 가능한 Part Number 수 | `inventory-status.json`의 검색 대상 | 최신 갱신 시각과 혼동하지 않도록 “검색 대상” 수로 표시 |
| 결과 요약 | 일치 결과 수 | 검색 결과 | 정확 일치/유사 일치/결과 없음 상태별 문구 제공 |
| 결과 목록 | Part Number | `inventory-status.json`, alias 및 specs의 PN 관계 | 대표 PN 표시, 검색한 alias와 다른 대표 PN이면 관계를 상세에서 설명 가능 |
| 결과 목록 | 제조사 | `product-manufacturers.json`, `product-specs.json` | 확인된 값만 표시. 비어 있으면 “정보 없음” 또는 칸을 비움 |
| 결과 목록 | DB 품목그룹 | `product-item-groups.json` (`ECOUNT CLASS_CD`) | 매핑이 있을 때 그룹 코드를 표시하고 검색어 대상으로 사용 |
| 결과 목록 | 제품 정보/카테고리 | `product-specs.json`의 검증된 필드 | 검색용 설명을 임의 생성하지 않음. 카테고리 또는 짧은 주요 규격만 사용 |
| 결과 목록 | 재고 상태/구간 | `inventory-status.json`의 status/stockLevel | 정책 승인된 상태/구간만 표시. 수량처럼 보이는 값은 노출하지 않음 |
| 결과 목록 | 문서 표시 | `product-specs.json`의 source/ecd URL | 유효한 공식 문서 링크가 있을 때만 버튼/링크 표시 |
| 상세 | 규격 | `product-specs.json`의 `specs` | 명칭과 단위를 원문대로 보존. 없는 항목은 만들지 않음 |
| 상세 | 이전 PN/alias | `product-specs.json`, `product-aliases.json` | 확인된 관계만 표시. 입력 PN과 대표 PN 관계를 명확히 표시 |
| 상세 | 변경/대체 후보 | `product-candidates.json` | 후보가 있을 때만 표시하고 확정 대체품처럼 표현하지 않음 |
| 상세 | 대표 이미지 | 로컬 이미지 인덱스/제품 이미지 | 실제 인덱스에 있고 해당 PN과 연결된 경우만 표시. 현재 인덱스 커버리지는 매우 제한적 |
| 문의 | 견적/제품 문의 | `contact.html` 문의 폼 | 선택한 PN을 query parameter로 전달하고 문의 폼의 제품 상세 항목에 미리 입력 |
| 추천 | 추천 재고 제품 | 재고 + 제조사 매핑 | 현재 Johanson 재고 제품 추천 원칙 유지, 검색 결과보다 시각적 우선순위를 낮춤 |

## 기본 동작

1. 첫 화면은 검색 입력을 중심으로 보여주며, 검색 전에는 제품 전체 목록을 한 번에 펼치지 않는다.
2. 검색 후 결과 표의 행/버튼을 선택하면 같은 페이지 상세 영역이 해당 제품 정보로 갱신된다.
3. 정확 Part Number가 최우선이다. Part Number 부분일치 다음에 제조사/카테고리/규격 필드/품목그룹 코드 일치를 표시하며, 최대 50개로 제한한다.
4. 드롭다운 없이 검색어로 Part Number, 제조사, 카테고리, 규격명/값, ECOUNT 품목그룹을 함께 찾는다. 관련도순으로 최대 50개를 보여준다.
5. 제조사·카테고리·품목그룹이 없는 상품은 빈 정보로 둔다.
6. 상세 문서, 후보, 이미지, 규격은 해당 데이터가 존재할 때만 노출한다.
7. 검색 결과가 없거나 데이터 로드에 실패한 경우 각각 구분된 한국어/영어 메시지를 제공한다.
8. 모바일에서는 표 영역 안에서 가로 스크롤하고, 상세는 결과 아래에 배치한다.

## 현재 데이터로 가능한 범위와 확인 필요 항목

2026-11-19 설계 시점에 파일을 읽어 확인한 값:

- 재고 검색 대상: 22,106개 PN. 파일의 `updatedAt`은 `2026-11-18T23:00:23.002Z`이며 기준일은 `20261119`다.
- 제조사 매핑: 2,630개 PN.
- 제품 규격: 1,640개 PN.
- alias 레코드: 448개.
- 대체 후보가 등록된 원 PN: 18개.
- 이미지 인덱스: 1개 항목.
- ECOUNT 품목그룹 인덱스: 아직 생성 전. ECOUNT Master 응답에 `CLASS_CD`가 있는 경우 이를 추출해 `product-item-groups.json`을 채우도록 동기화에 연결했으며, 첫 실행 로그에서 실제 커버리지를 확인해야 한다.

따라서 Part Number 검색 결과 표와 재고 상태는 전체 검색 대상에 적용할 수 있지만, 제조사/카테고리/기술 필터는 결과별 데이터 커버리지가 부분적이다. 설계/구현에서는 빈 데이터를 명시적으로 허용해야 한다.

추가로 업무 기준을 확인할 항목:

- 재고 구간/문구의 공개 기준과 데이터 신선도 표기. 현재 파일은 갱신 시각도 보여주기 전에 최신성 확인 필요.
- 추가로 노출할 재고 freshness 문구의 운영 기준. 현재 공개 화면은 재고 상태/구간을 사용한다.

## 진행 결과 — 2026-11-19

- 1단계: 정보 구조와 필드 규칙 확정.
- 2단계: 검색창, 결과 표, 조건 선택, 제품 상세와 보조 추천 영역을 구현.
- 3단계: 기존 정확/부분/alias 검색, 재고 상태, 제품 규격, 공식 문서 및 대체 후보 표시를 새 레이아웃에 연결. Contact 페이지 문의 폼에 제품번호를 미리 입력하는 동선 추가.
- 4단계: 드롭다운을 제거하고 검색창에서 제조사/카테고리/규격/품목그룹을 검색하도록 변경. Part Number 접두 일치를 우선하고 최대 50개 결과로 제한.
- 5단계: KO/EN 문구·검색 placeholder·ARIA 라벨 및 모바일 화면을 확인. 모바일에서는 표 영역 안에서 가로 스크롤하고 상세 패널은 결과 아래에 둔다.
- 실제 프로젝트 JSON을 읽는 Chromium 브라우저 확인: 정확 PN, alias, 규격/문서, KO/EN, 390px 폭 모두 통과. 페이지 오류 없음, 모바일 문서 전체 가로 넘침 없음.
- 로딩 개선: 6개 데이터 파일을 병렬로 불러오고 재고 목록을 한 번만 구성한다. alias 역색인을 사용하고 브라우저 기본 HTTP 캐시를 사용할 수 있도록 `no-store`를 제거했다.
